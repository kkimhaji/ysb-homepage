# 연세대학교 경영대학 오퍼레이션 전공 홈페이지

기존 Google Sites (https://sites.google.com/view/yonseiscom) 의 내용을 옮겨
반응형 정적 웹사이트로 새로 만든 것입니다. 한국어가 기본이고 우측 상단에서 영어로 전환할 수 있습니다.

## 바로 보기

폴더 안에서 아래 명령을 실행한 뒤 브라우저에서 http://localhost:8765 에 접속하세요.

    python3 -m http.server 8765

(index.html 을 그냥 더블클릭해서 열어도 대부분 동작하지만, 로컬 서버로 보는 편이 정확합니다.)

## 파일 구성

    index.html        홈
    faculty.html      전공 교수 소개
    admissions.html   석·박사 과정 입학 안내
    courses.html      교과목 소개
    students.html     재학생 현황
    alumni.html       졸업생 현황 + 졸업생 추천 글
    seminars.html     연구 세미나 시리즈
    news.html         소식

    assets/css/site.css   전체 디자인
    assets/js/site.js     언어 전환, 다크모드, 검색·필터, 스크롤 애니메이션
    assets/img/           사진을 넣는 곳 (README.md 참고)
    assets/img/brand/     연세대학교 경영대학 공식 로고
    assets/img/faculty/   교수 사진

    build.py          위 8개 HTML 을 생성하는 스크립트 (내용 데이터가 여기에 들어 있음)

## 내용을 고치는 두 가지 방법

**(1) build.py 를 고치고 다시 만들기 — 권장**

교수·재학생·졸업생·세미나 명단처럼 목록으로 된 내용은 `build.py` 안의 DATA 영역에
파이썬 리스트로 정리되어 있습니다. 한 줄씩 고치거나 추가한 뒤

    python3 build.py

를 실행하면 7개 HTML 이 한꺼번에 다시 만들어집니다. 한국어와 영어가 같은 줄에 붙어 있어
번역이 어긋날 일이 없습니다.

**(2) HTML 을 직접 고치기**

간단한 문구 수정이라면 HTML 파일을 직접 열어 고쳐도 됩니다.
다만 이렇게 고친 뒤에는 `build.py` 를 다시 실행하면 수정 내용이 사라지니 주의하세요.
HTML 안에서 한국어는 `class="ko"`, 영어는 `class="en"` 요소에 들어 있습니다. 둘 다 고쳐야 합니다.

## 채워 넣은 자료의 출처

- **공식 로고** — 연세대학교 경영대학 공식 사이트의 로고 파일을 `assets/img/brand/` 에 넣었습니다.
  헤더에는 밝은 배경용 `ysb-logo.png` 와 다크모드용 `ysb-logo-white.png` 를 테마에 따라 바꿔 표시하고,
  푸터에는 흰색 가로형 `ysb-logo-footer.png` 를 씁니다. `yonsei-seal.png` 는 예비용입니다.
  학교 공식 마크이므로 크기·비율·색을 임의로 변형하지 말고, 대외 공개 전에는 대학 UI 지침과 홍보팀 확인을 받는 편이 안전합니다.
- **교수 사진** — 연세대학교 경영대학 전임교수 페이지에서 받아 `assets/img/faculty/` 에 넣고 가로 900px 로 줄였습니다.
  명예교수 두 분은 경영대학 명예교수 페이지에서 받았습니다.
  배성주 교수님과 명예교수 두 분의 사진은 학교 사이트 원본이 100x130 밖에 되지 않아, 가로 600픽셀로 확대하고
  샤프닝을 적용해 넣었습니다. 다른 사진보다 다소 부드럽게 보입니다.
  원본 고해상도 파일이 있으면 `assets/img/faculty/` 의 `bae.jpg`, `kimky.jpg`, `kimth.jpg` 를 덮어쓰기만 하면 됩니다.
- **개인 홈페이지 링크** — 전임교수는 경영대학 전임교수 상세 페이지로, 명예교수는 경영대학 명예교수 상세 페이지로 연결했습니다.
  명예교수 카드에는 현재 소속(삼일문화재단, aSSIST) 링크도 함께 넣었습니다.
- **교과목** — 기존 홈페이지의 교과목 표를 그대로 옮겼습니다. 8개 과목과 학점, 수업 내용이 들어 있습니다.
- **이수 요건** — `ODI-OM 석박사 내규` PDF 를 정리해 석사 30학점 / 박사 36학점 표와 종합시험·졸업 요건으로 만들었습니다.
  내규는 2014년 개정본 기준이므로, 이후 변경된 내용이 있으면 `build.py` 의 `REQ_MS`, `REQ_PHD` 에서 고쳐 주세요.


## 소식 관리

소식은 따로 `news.html` 페이지가 있고 상단 메뉴에서 바로 갈 수 있습니다.
홈 화면 세미나 섹션 아래에는 최근 다섯 건만 나오고, 옆의 단추로 전체 소식 페이지로 넘어갑니다. 교수, 재학생, 졸업생 소식을 나누지 않고
한 목록에 함께 올립니다. 호칭이 이미 대상을 구분해 주기 때문입니다.

새 소식은 `build.py` 의 `NEWS` 리스트 맨 위에 한 줄 추가하고 다시 빌드하면 됩니다.

    ("2026-11", "honor",
     "이연주 동문(석사 2019), Penn State University 조교수로 임용되었습니다.",
     "Yeonjoo Lee (M.S. 2019) has been appointed Assistant Professor at Penn State University.",
     ""),

- 사건월은 `"YYYY-MM"` 입니다. 정확한 날짜를 몰라도 되도록 월까지만 씁니다.
- 분류는 `honor`, `research`, `program` 셋뿐입니다. 빈 문자열로 두면 배지가 나오지 않습니다.
- 영문은 비워도 됩니다. 비우면 영어 화면에도 국문이 그대로 나옵니다. 누락보다 낫습니다.
- 홈에는 최근 다섯 건만 나옵니다. 소식 페이지에는 전부 연도별로 나옵니다.
- `NEWS` 를 비우면 소식 섹션 자체가 사라집니다. 빈 목록이 남지 않습니다.

**소식에 올리지 않는 것**
세미나 개별 회차는 `SEMINARS` 에만 넣습니다. 연도만 아는 사실은 졸업생 표에 넣습니다.
학사 공지와 장학 공지는 일반대학원과 경영대학이 이미 담당하므로 옮겨 적지 않습니다.

## 영문 이름

영어 화면에서 세미나 연사, 졸업생, 재학생 이름을 로마자로 보여 줍니다. `build.py` 의
두 표에 한글 이름을 키로 적습니다.

- `NAMES_EN` 본인이 쓰는 철자를 확인한 이름입니다. 영어 화면에 그대로 나옵니다.
- `NAMES_EN_UNVERIFIED` 확인하지 못해 관례 표기로 적어 둔 이름입니다. 영어 화면에는
  나오지 않습니다. 본인에게 확인한 뒤 `NAMES_EN` 으로 옮기면 그때부터 나옵니다.

확인 없이 내보내지 않는 데는 이유가 있습니다. 표기법대로 옮기면 우리 전공 교수 일곱 분 중
네 분의 이름이 틀리게 나옵니다. 민순홍 교수는 Sunhong 이 아니라 Soonhong, 배성주 교수는
Seongju 가 아니라 Sungjoo 입니다. 이름을 틀리게 쓰는 것은 한글로 두는 것보다 나쁩니다.

빌드하면 확인할 인원이 몇 명 남았는지 나옵니다. 재학생은 단톡방으로, 졸업생은 연락되는
분부터 철자를 받아 옮기면 됩니다. 급하게 전부 내보내야 하면 `SHOW_UNVERIFIED_NAMES` 를
`True` 로 바꾸면 되지만, 게시 전에는 권하지 않습니다.

같은 한글 이름의 다른 사람이 생기면 `("김효진", "Keimyung University")` 처럼 소속 영문을
붙인 키로 따로 적습니다.

## 졸업생 추천 글

`build.py` 의 `TESTIMONIALS` 목록에 한 편씩 들어 있습니다. 새 글을 받으면 `dict` 하나를
뒤에 붙이면 됩니다. 졸업생 페이지에는 모두 전문으로 실리고, 홈 화면에는 첫 번째 글의
발췌만 나옵니다. 글이 두 편 이상이 되면 제목과 설명이 자동으로 복수형으로 바뀝니다.

    dict(
      name=("홍길동", "Gildong Hong"),
      meta=("2026년 8월 박사 졸업 · 現 ○○대학교", "Ph.D. 2026 · now at ..."),
      excerpt=[("홈에 실을 문단", "English"), ],
      letter=[("전문 첫 문단", "English"), ("둘째 문단", "English"), ],
    ),

본인이 쓴 글이므로 문장을 다듬지 않고 받은 그대로 싣습니다. 영문은 본인이 쓴 것이 있으면
그것을, 없으면 번역하되 본인 확인을 받습니다. 학계로 간 동문과 외국인 졸업생의 글을 받아
두면 박사과정 지원자와 외국인 지원자 모두에게 도움이 됩니다.

## 재학생 연구 실적

재학생 카드에 게재 논문과 학회 발표를 싣습니다. `build.py` 의 `STUDENT_WORK` 에 이름을
키로 적습니다.

    "홍길동": [
      ("pub",  "홍길동, 정승환 (2026). 논문 제목. 학술지명.", "Hong, G., Jung, S. (2026). Title. Journal."),
      ("conf", "홍길동 (2026). 발표 제목. 학회명.",           "Hong, G. (2026). Title. Conference."),
    ],

- `pub` 은 게재 또는 게재 확정 논문, `conf` 는 학회 발표입니다. 카드에는 논문이 먼저 나옵니다.
- 발표까지 넣는 것은 박사과정 초기나 석사과정 학생도 실적을 보일 수 있게 하려는 것입니다.
- 실적이 없는 학생은 아예 적지 않습니다. 그러면 카드에 이 칸이 생기지 않습니다.
  "실적 없음" 같은 빈 칸을 만들면 학생 사이에 대비만 두드러집니다.
- 학기 초에 한 번 갱신합니다. 페이지 아래의 확인 시점 문구도 함께 고칩니다.

재학생 카드의 `STUDENTS` 목록과는 따로 둡니다. 명단을 고치다가 실적 칸을 건드리지 않게
하려는 것입니다.

## 명단 갱신

`build.py` 상단의 `LAST_REVIEWED_KO` / `LAST_REVIEWED_EN` 을 학기마다 함께 고치세요.
재학생과 졸업생 페이지 아래에 "이 명단은 언제 확인한 것인지"와 정보 수정 요청 메일 링크가
자동으로 붙습니다. 표가 낡더라도 사이트가 사실과 다른 말을 하지 않게 하는 장치입니다.

졸업하는 학생은 `STUDENTS` 에서 빼고 `ALUMNI_MS` 로 옮겨야 합니다. 이 이동이 밀리면
사이트가 곧바로 틀린 정보를 말하기 시작합니다. 학기 초 빌드 때 함께 하시면 됩니다.

`STUDENTS` 의 마지막 두 칸은 출신 학교입니다. 국문과 영문 순서입니다. 아직 비어 있어서
카드에는 "출신 학교 미기재"라는 흐린 글씨가 자리만 잡고 있습니다. 값을 넣으면 그 글씨가
사라지고 학교 이름이 들어갑니다. 빌드할 때 아직 비어 있는 학생 이름이 목록으로 출력되니,
게시 전에 그 목록이 사라졌는지 확인하시면 됩니다.

## 교수 상시 활동

교수 소개 페이지의 카드에 연구 관심 분야 아래로 나옵니다. `build.py` 의 `FACULTY_ROLES` 입니다.
편집위원, 학회 임원처럼 날짜가 지나도 낡지 않는 직함만 적습니다.
논문 게재나 수상처럼 시점이 있는 일은 여기가 아니라 `NEWS` 에 넣으세요.

한 분당 두 건까지만 두시기를 권합니다. 임기가 있는 직함은 연도를 함께 적어야 합니다.
임기가 끝났는데 현직처럼 적혀 있으면 사이트가 조용히 사실과 달라집니다.


## 메일로 보낼 때

구글은 `.js` 파일을 첨부에서 막습니다. 압축 안에 들어 있어도 똑같이 막아서,
받는 쪽이 Gmail 이나 구글 워크스페이스를 쓰면 메일이 반송됩니다.
`552-5.7.0 This message was blocked because its content presents a potential
security issue` 라는 메시지가 옵니다.

그래서 메일에 붙일 때는 `package_mail.py` 로 따로 만듭니다. `site.js` 를 각 페이지
안에 직접 넣고 파일 자체는 빼서 담습니다. 보이는 것과 동작은 원본과 같습니다.

    python3 build.py && python3 package_mail.py

결과물은 `_mail/` 아래에 생깁니다. 이 방식은 첨부용일 뿐이고, 실제로 서버에 올릴
때는 `build.py` 가 만든 원본을 그대로 씁니다. 스크립트가 파일 하나로 분리되어 있어야
브라우저가 한 번 받아 두고 여러 페이지에서 재사용합니다.

## 어투 기준

학과 홈페이지의 어투는 두 방향 모두로 벗어나기 쉽습니다. 아래 가운데를 지키면 됩니다.

- **홍보성으로 기울지 않기.** "최선을 다하고 있습니다", "세계 최고 수준", "다양한 분야에서
  활발하게" 같은 문장은 어느 기관에 붙여도 말이 되므로 아무 정보도 주지 않습니다.
- **구어체나 문학적 표현으로 기울지 않기.** "이곳을 거쳤습니다", "자리를 잡았고", "덜 버겁습니다",
  "토론이 끝까지 갑니다" 같은 표현은 블로그 어투입니다.
- **주체를 밝히기.** 문단 첫 문장에는 "본 전공은"을 넣어 누가 하는 일인지 분명히 합니다.
  "저희"는 말하는 사람이 앞에 있을 때 쓰는 자칭이라 소개문에는 맞지 않습니다.
- **종결어미를 한 등급으로.** 한 목록 안에서 "-합니다"와 "-한다"가 섞이지 않게 합니다.
- **제목은 명사구로.** 아래 "제목 기준"을 보세요.
- **높임은 사람에게만.** 기관 문서에서 초빙 대상을 "교수님"으로 높이지 않습니다.

KAIST AI대학원, POSTECH, UNIST의 실제 제목 문구를 모아 대조해서 정한 기준입니다.

  명사구였습니다. 두 가지 꼴을 씁니다. 하나는 "전공 교과목", "장학 제도" 같은 맨명사이고,
  다른 하나는 "가치의 흐름을 설계하는 학문", "매 학기 열리는 연구 세미나"처럼 수식절에
  머리명사를 붙인 꼴입니다. 뒤쪽이 밋밋해지지 않게 해 줍니다.
- **명사구 제목에는 마침표를 찍지 않습니다.** 수집 자료에서 한 건도 없었습니다.
- **종결형 문장 제목은 사이트 전체에 한 곳만 둡니다.** 지금은 홈 맨 아래 모집 배너
  "열정을 갖춘 석·박사 과정 학생을 모집합니다" 하나입니다. `build.py`의
  `HEADING_SENTENCE_OK`에 예외로 적어 두었고, 그 밖에 종결형 제목이 생기면 빌드할 때
  "제목 점검" 경고가 뜹니다.
- **쓰지 않는 것.** 독자에게 말을 거는 의문문("궁금한 점이 있으신가요?"),
  "~한다는 것" 명사절, 해요체, 청유형, 느낌표. 모두 수집 자료에서 한 건도 없었습니다.
- **제목 아래 한 줄(dek)은 "-습니다"가 맞습니다.** 제목은 명사로, 본문은 합쇼체로 갑니다.
  이건 취향이 아니라 자리에 따라 갈리는 규칙입니다.
- **영문 제목은 명사구에 문장형 대문자(sentence case)입니다.** "Research seminar series"처럼
  첫 글자만 대문자로 씁니다. 물음표로 끝내지 않습니다.

## 메뉴

상단 메뉴는 여덟 개입니다. 화면 폭이 1200px 이상이면 가로 한 줄로, 그 아래에서는 오른쪽
위 단추를 누르면 펼쳐지는 햄버거 메뉴로 접힙니다. 휴대폰과 태블릿은 늘 햄버거 메뉴라
메뉴가 늘어도 줄바꿈이 생기지 않습니다.

기준이 1200px 인 것은 영문 화면 때문입니다. 영문 메뉴 글자가 길어서 그보다 좁으면 로고
옆 전공 이름이 잘립니다. 메뉴를 하나 더 늘리면 이 기준도 다시 재 봐야 합니다.

## 디자인 기준

AI가 만든 티로 지목되는 것들입니다. 나중에 손볼 때 다시 들어오지 않게 하세요.

- 반투명 배경에 흐림 효과를 준 유리 질감 패널, 알약 모양 배지
- 글자에 그라디언트를 입히는 것 (background-clip:text)
- 둥근 사각형 타일 안에 든 아이콘
- 모든 요소가 같은 모서리 반경을 쓰는 것
- 카드 위에 얹는 색 그라디언트 바
- 마우스를 올리면 카드가 들리면서 그림자가 생기는 것

스크롤 효과와 배경 애니메이션, 숫자 세어 올리기는 이 목록에서 제외합니다.
한 번 뺐다가 되돌린 항목들입니다.
스크롤에 따라 블록이 떠오르는 효과는 `.rv` 클래스가 붙은 요소에 걸리고, 배경의 망 그림은
선이 흐르고 점이 커졌다 작아집니다. 값은 `assets/css/site.css`의 reveal 구역에 있습니다.
숫자는 `data-count` 가 붙은 요소가 화면에 들어올 때 0부터 굴러갑니다. 마크업에는
처음부터 실제 값이 적혀 있어 자바스크립트가 꺼져 있어도 숫자는 제대로 보이고,
굴리는 도중 멈추더라도 2초 뒤에는 정확한 값으로 맞춰집니다.
`prefers-reduced-motion`을 켠 사용자에게는 셋 다 꺼집니다.
- 섹션마다 붙는 영어 대문자 라벨
- 같은 추상 그래픽을 여러 곳에 반복해서 쓰는 것
- 정확히 셀 수 있는 수에 +를 붙이는 것
- 유행하는 디스플레이 서체 (Instrument Serif, Playfair Display 등). 본문 세리프는
  Iowan Old Style과 Georgia처럼 운영체제에 들어 있는 것을 쓴다.
- 카드마다 같은 아이콘을 반복해서 붙이는 것. 서로 다른 것을 가리킬 때만 아이콘을 쓴다.
- 카드 왼쪽 가장자리의 색 막대
- 라틴 소문자용 자간(letter-spacing)을 한글 라벨에 그대로 거는 것
- 링크가 아닌 글자에 호버하면 밑줄이 생기는 것
- 빈 칸을 줄표(—)로 채운 표. 한 열이 통째로 비면 열을 내린다.

## 문구를 고칠 때

이 사이트는 AI가 만들었기 때문에, 손볼 때 AI 티가 다시 섞여 들어오기 쉽습니다.
`python3 build.py` 를 실행하면 마지막에 표현 점검이 돌아가고, 아래 표현이 다시 나타나면 경고합니다.

    이모지, em dash(—), "세계 최고", "최선을 다", "다양한 분야에서",
    delve, seamless, elevate, robust

점검에 안 걸리지만 조심할 것들입니다.

- **세 개씩 나열하는 습관.** "A하고, B하며, C하는" 구조가 문단마다 반복되면 티가 납니다.
  두 개나 네 개로 섞으세요.
- **대구를 맞춘 두 문장.** "A하되 B합니다. ~를 위한 선택입니다." 같은 형태입니다.
- **주어 없는 좋은 말.** 숫자도 이름도 날짜도 없이 좋은 말만 이어지는 문단이 가장 큰 신호입니다.
  "전임 교수 6명이 박사 3명을 지도합니다"처럼 셀 수 있는 사실로 바꾸세요.
- **정확히 셀 수 있는 수에 붙는 +.** 6+ 전임 교수 같은 표기는 쓰지 않습니다.
- **구체적인 것을 빼지 않기.** 연구실 호실, 전화번호, 담당자 이름, 잡다한 예외 안내처럼
  사람이 운영하는 사이트에 자연히 쌓이는 것들이 있어야 사람이 만든 것처럼 읽힙니다.
